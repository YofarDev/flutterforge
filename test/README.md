# Tests

Run `./scripts/fverify.sh --fix` before finishing any change (fix + format,
then format check, analyze, and the full suite). Patterns and mocktail usage
live in the [flutter-testing skill](../.agents/skills/flutter-testing/SKILL.md);
this file only states what this project tests.

## Test behavior at boundaries, not plumbing

Each test should fail only when something a user or another layer relies on
breaks. Write:

| Kind | Where | Covers |
| --- | --- | --- |
| Architecture gate | `architecture_test.dart` | Layering rules (one test; keep it green) |
| DI smoke | `core/di/service_locator_test.dart` | Every registration resolves |
| Repository | `features/<f>/data/repositories/` | Success, and exceptions/malformed payloads becoming a typed `Failure` |
| Cubit | `features/<f>/presentation/bloc/` | The state transitions this cubit owns (success, failure, its own rules) |
| Screen | `features/<f>/presentation/screens/` | What each state renders, and user actions |
| Flow | `features/<f>/*_flow_test.dart` | The feature module's real registrations and route over a fake data source |
| Shared mechanism | `core/` | Tested once where it is defined |

Do not write:

- tests of framework or config (theme brightness, "uses Material 3");
- tests that a widget or provider exists ("renders XView", "provides XCubit") —
  a behavior test already fails if it is missing;
- forwarding tests ("service delegates to repository");
- per-feature copies of shared mechanics. Request ordering and close safety
  come from `LatestRequestWins` (`core/bloc/`), tested in
  `core/bloc/latest_request_wins_test.dart`; failure copy comes from
  `localizeFailure`, tested in `core/l10n/failure_localization_test.dart`.

A feature generated by `./scripts/fgen.sh` starts with repository, cubit,
screen and flow tests, and its repository check in the DI smoke test. Replace
the placeholder data in them when real I/O lands.

## Fakes

Flow tests replace only the data-source seam; everything downstream stays
real. A feature flow test passes a fake to its module
(`registerXFeature(GetIt.asNewInstance(), remoteDataSource: fake)`); the
cross-feature flows in `features/home/` use `setupServiceLocator(...Override)`
and the fakes in `support/`.
